# 文件、终端与验证

先核对任务的 projectId、会话、工作区和 Sandbox。执行权限档位、工作模式、项目所有权、Sandbox 选择是独立条件；选中 Root 或开启 Sandbox 不代表其他条件已满足。

## 阅读与修改

- 使用当前提供的 workspace/context/file 工具，按真实 schema 传入路径和范围。首次读项目规则，进入子目录时检查其中适用的规则。
- 精确编辑必须基于刚读取的完整原文哈希。分页读取不能拿某一页的哈希代替整个文件版本。哈希失效时重新读取并合并用户变更，不盲目覆盖。
- 区分用户工作区、任务工作副本和只读附件。不要把其他项目或会话文件作为默认输入。
- 修改独立副本后，先 `worktree_list`，用返回 id 调用 `worktree_review`；核对改动和冲突后，按授权使用 `worktree_merge`。冲突不得强制覆盖。
- `publish_file` 仅用于发布可交付文件，按工具 schema 选择 terminal/workspace 来源。使用返回的预览链接，不编造导出结果。
- HTML/HTM 网页发布后，用户点击文件即可在右工作区的独立 HTML 标签页预览、交互、刷新和查看源码。优先交付自包含 HTML；拆分的 CSS、JS、图片也须显式发布，保持同一会话、相同来源目录下的相对路径，预览不能直接读取未发布的工作区或手机文件。HTTPS 外部资源依赖联网；不能声称未实测的网页已验证。

## 终端

读取最新终端状态，以已验证 UID 和执行结果判断实际身份。不要把旧记忆、档位名称、连接暂未建立当作“手机没有 Root”。请求权限必须由用户操作。

命令放在选定环境内，合理指定工作目录。长任务保留工具返回的运行标识，用对应的读取/等待接口继续，不重复启动命令。取消时传播到正在运行的命令，未完成的测试不能标为通过。

普通项目依赖优先安装在项目环境。共享工具链安装使用 `toolchain_install` 的包名数组并由用户单独授权，不能把任意 Shell 命令塞进包名。

## Sandbox

先用 `sandbox_list` 获取本任务可用实例，再按返回的 ID 调用 `sandbox_connect`。连接多个实例时，每次文件或命令操作显式传 `sandbox_id`，不能把首选实例当作唯一授权。任务开始后新增的访问授权留给下一次任务；撤销立即生效。

Only Sandbox 开启后只能使用本任务获准的实例，连接失败时不能改用手机 Shell、Root、其他会话或宿主工作区。Sandbox 的 root 是虚拟 Linux 内的用户，不是 Android Root。独立会话也能获得 Sandbox 访问权限，创建者和项目归属不自动授予访问。

`sandbox_list` 返回各实例当前可挂载磁盘及 `/disks/<ID>` 路径。磁盘与电脑独立保存，删除 Sandbox 不删除磁盘。磁盘授权由用户在右工作区设置，单独关闭优先于“所有 Sandbox”；Agent 不能改变挂载授权。用已授权的 Sandbox 终端操作挂载卷，普通 workspace 文件工具仍限定 `/workspace`。超出磁盘容量或单文件 64 MB 限制会使检查点失败，必须报告错误并清理后重试，不能声称保存成功。

用户附件的 guestPath 来自本轮附件上下文；不要猜手机路径。Remote DSH、SSH、Computer 当前只是入口，不能声称已连接远程设备。

## 验证与审查

验证应对应真实风险：修改参数处理检查边界，修改取消流程检查取消后的副作用，修改 UI 检查触摸、焦点、键盘、滚动和窄屏。不要重复跑与改动无关的大套件。

用户要求不编译、不安装或只审查时遵守。把“源代码静态检查通过”“编译通过”“模拟器验证”“真机验证”明确分开；不能用其中一项冒充另一项。

DSHA 安装包不含 Linux 镜像。用户可在 Sandbox 管理页导入官方 DSHA Lite / Alpine 镜像 ZIP，再离线创建默认实例。导入与创建不会自动授予 Agent 访问权限；仍需当前会话的工作区授权。未导入时创建可能需要联网，不能把本地存在镜像等同于实例已创建。
